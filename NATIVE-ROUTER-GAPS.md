# TanStack Native Router gaps

This comparison uses the native implementation in this checkout as the baseline and assumes an iOS and Android app. It compares capabilities and integration effort. [Current native implementation](./NATIVE-PARITY.md)

## Compared with React Navigation

| Area | Gap in TanStack Native Router | What React Navigation provides |
| --- | --- | --- |
| Gesture-driven drawer | Drawer state and Back handling exist. The default host is a controlled sidebar. A swipe-driven drawer requires a custom host. [Native hosts](./NATIVE-PARITY.md#native-host-reconciliation) | A [Drawer Navigator](https://reactnavigation.org/docs/drawer-navigator/) with gesture and presentation options. |
| Swipeable tabs | The example demonstrates a Material-style pager via the Standard Navigation adapter. Apps supply the pager host. [Adapter](./STANDARD-NAVIGATION.md) | A dedicated [Material Top Tabs Navigator](https://reactnavigation.org/docs/material-top-tab-navigator/). |
| Incoming links and notifications | Typed destination matching exists. Link source integration, destination-to-container mapping, and stricter prefix handling remain open. For a cold notification that opens a chat, the app needs to decide which stack owns it and what Back should do. [Linking gaps](./NATIVE-PARITY.md#remaining-substantial-gaps) | [Linking configuration](https://reactnavigation.org/docs/configuring-links/) for nested state plus [initial URL and subscription hooks](https://reactnavigation.org/docs/deep-linking/) for custom sources. The app still supplies notification handling and platform associations. |
| Navigator events and imperative controls | Push, replace, reuse, pop, reset, blocking, and Back bubbling are available. Integrations that depend on particular navigator events, action payloads, or state APIs need to map those contracts. [Presentation ownership](./NATIVE-PARITY.md#presentation-and-execution-ownership) · [Adapter semantics](./STANDARD-NAVIGATION.md) | Documented [navigation actions](https://reactnavigation.org/docs/navigation-object/) and [navigator events](https://reactnavigation.org/docs/navigation-events/). |
| Modal variants | Native form sheets and contained modals are implemented. Other variants can use React Native Modal. Compare the exact host options, stacking, transitions, and dismissal semantics required by the app. [Native hosts](./NATIVE-PARITY.md#native-host-reconciliation) | [Native-stack presentation options](https://reactnavigation.org/docs/native-stack-navigator/) configure multiple modal variants through the navigator. |
| Runtime-defined screen inventories | Guards and redirects control access to typed routes, and individual visits can own nested navigators. A flow that changes which screens are registered at runtime needs an explicit design around the route tree. [Nested navigator ownership](./NATIVE-PARITY.md#per-visit-nested-navigator-ownership) | The [dynamic API](https://reactnavigation.org/docs/static-vs-dynamic/) lets React components determine which screens are registered. |

## Compared with Expo Router

| Area | Gap in TanStack Native Router | What Expo Router provides |
| --- | --- | --- |
| Native link normalization | The incoming-link gap above also applies here. There is no equivalent documented hook in this checkout for rewriting stale or third-party URLs before route resolution. | [`+native-intent`](https://docs.expo.dev/router/advanced/native-intent/) provides a dedicated entry point for that transformation. |
| Route-aware iOS interactions | Destination previews, link context menus, and Apple Zoom transitions need separate native UI integration. | [Link previews and menus](https://docs.expo.dev/router/reference/link-preview/) and [route-linked zoom transitions](https://docs.expo.dev/router/advanced/zoom-transition/). |
| Native toolbar and split view | Compare specific toolbar controls against the native header options already available. A system split-view layout needs a separate host. | [Stack Toolbar](https://docs.expo.dev/router/advanced/stack-toolbar/) and an [alpha iOS split-view navigator](https://docs.expo.dev/versions/latest/sdk/router/split-view/). |
| Route discovery and test fixtures | TanStack generates a route tree. Expo's browsable route listing and in-memory filesystem fixture helpers would need equivalents for teams that rely on them. | [`/_sitemap`](https://docs.expo.dev/router/reference/sitemap/) for debugging and [`renderRouter`](https://docs.expo.dev/router/reference/testing/) for testing route trees from an initial URL. |
| Metro async route bundling | The checkout integrates Metro for native builds and Start RPC. An equivalent automatic lazy-bundling workflow for native route files is undocumented. [Metro configuration](./examples/react/start-native/native/metro.config.cjs) | [Async routes](https://docs.expo.dev/router/web/async-routes/) on native are experimental and development-only. |
| Native React Server Components | TanStack Start's native transport supports typed server calls. Streaming a server-rendered React component tree to a native app is a separate capability. [Native server functions](./NATIVE-PARITY.md#shared-route-definitions-and-server-functions) | [Universal React Server Components](https://docs.expo.dev/guides/server-components/) include native rendering in technical preview. |
| Expo server deployment | If the native app uses Start, it points at a configured backend origin. The Expo-specific workflow for pairing a native build with a versioned deployed server needs separate deployment setup. [Native Start configuration](./NATIVE-PARITY.md#shared-route-definitions-and-server-functions) | An integrated [native server deployment workflow](https://docs.expo.dev/router/web/api-routes/#native-deployment) with Expo Hosting. |

## Covered by TanStack

- **Routing and presentation.** File-based routes, typed destinations, validated path and search params, nested stacks and tabs, independent visits, sheets, removal blockers, and versioned restoration. [Route API](./UNIVERSAL-NATIVE-EXPERIMENT.md#route-and-navigation-apis) · [Current native implementation](./NATIVE-PARITY.md)
- **Route execution.** Loaders, guards, redirects, cancellation, and invalidation are part of the route lifecycle. Retained visits can refresh after a mutation. [Execution ownership](./NATIVE-PARITY.md#presentation-and-execution-ownership)
- **Backend capabilities with Start.** A native app can call typed `createServerFn` functions and HTTP API routes on a deployed backend. Start also supplies server middleware. Web prerendering, SSR, HTML metadata, and web route splitting fall outside this native-only comparison. [Native server functions](./NATIVE-PARITY.md#shared-route-definitions-and-server-functions) · [API route example](./examples/react/start-native/src/routes/api.venues.ts) · [Start middleware](./docs/start/framework/react/guide/middleware.md)
